# codeunlimited 1.8 Experiment Measurement Design

**Date:** 2026-09-04  
**Status:** Design approved; self-reviewed specification ready for review  
**Base:** `codex/v1.7-performance` at `a8036035126221a1903e3a9845f325e9621e8434`

## Goal

Add a privacy-preserving experiment ledger that measures exact observed token
usage for bounded work windows and compares token usage per completed task.
Use it to compare the completed 1.7 sprint with the completed 1.8 sprint while
stating clearly that an exact observation is not an exact causal estimate.

## Meaning of “exact”

An experiment total is exact when it is the saturating sum of the integer token
counters present in recognized local Claude Code and Codex records whose
timestamps fall inside the experiment's half-open interval:

```text
started_unix <= request timestamp < finished_unix
```

The saved record retains the integer numerators (`input_tokens`,
`output_tokens`, and `completed_tasks`) used by every comparison. Displayed
percentages are rounded views derived from those integers. Missing or invalid
timestamps cannot be assigned to an interval; the record reports their count
and is marked incomplete. An incomplete record cannot be presented as an exact
comparison.

“Observed savings” means the arithmetic difference in input tokens per declared
completed task between two non-overlapping records. It does not prove that
codeunlimited caused the difference. Differences in task scope, difficulty,
model behavior, tool use, and provider accounting remain possible confounders.

## User workflow

The new nested command is `codeunlimited experiment`:

```text
codeunlimited experiment start <NAME> [PATH]
codeunlimited experiment finish <NAME> --tasks <N> [PATH] [--json]
codeunlimited experiment record <NAME> --from <RFC3339> --to <RFC3339> --tasks <N> [PATH] [--json]
codeunlimited experiment compare <CONTROL> <TREATMENT> [PATH] [--json]
codeunlimited experiment list [PATH] [--json]
```

`start` captures the current Unix timestamp before writing state. `finish`
captures the end timestamp before scanning logs, requires at least one declared
completed task, aggregates the interval, and atomically completes the record.
`record` backfills a completed record for an explicit historical RFC 3339
interval. `compare` refuses active, incomplete, empty, or overlapping records.
`list` prints names, status, windows, task counts, and aggregate token totals.

Names are unique within one project and must contain only ASCII letters,
digits, `.`, `_`, or `-`, with a maximum length of 64 bytes. Creating a record
with an existing name fails without changing state. Finishing an already
finished record prints the saved result and succeeds without rescanning, making
automation retries idempotent.

## State model

Experiments live in `.codeunlimited.experiments.json` at the selected project
root. The whole document is replaced atomically through the existing safe I/O
layer. A symlinked state path, unreadable file, malformed JSON, unsupported
schema version, or invalid record fails visibly and preserves the original
bytes.

Schema version 1 stores a map keyed by experiment name. Each record contains:

```text
name
started_unix
finished_unix | null
completed_tasks | null
status = active | complete
complete_accounting
records_without_timestamp
totals | null
```

Completed totals contain:

```text
requests
sessions
uncached_input_tokens
cache_read_input_tokens
cache_write_5m_input_tokens
cache_write_1h_input_tokens
input_tokens
output_tokens
total_tokens
```

`input_tokens` is the saturating sum of the four input categories;
`total_tokens` is input plus output. Sessions are counted by the composite
identity `(source, project, session)`. All arithmetic saturates rather than
wrapping.

## Comparison semantics

The comparison JSON preserves the exact integer totals and task counts for both
records. It also exposes rounded presentation fields:

```text
control_input_tokens_per_task
treatment_input_tokens_per_task
observed_input_delta_per_task
observed_input_change_percent
observed_capacity_change_percent
causality = observational
```

For one completed task in each sprint, the per-task delta is an exact integer.
For other task counts, the source totals and denominators remain the exact
representation; decimal fields are explicitly presentation-only. Capacity
change uses `control_per_task / treatment_per_task - 1`, matching the existing
“more work fits” interpretation. Zero-token records cannot be compared.

Text and JSON always call this an “observed difference,” not proven or
guaranteed savings. Output includes a low-confidence warning when either side
has fewer than three completed tasks.

## Existing delta safety

The current `delta` command emits a directional verdict even when only one or
two new requests exist. Version 1.8 introduces a fixed minimum of 100 retained
post-baseline requests per source. Below that threshold, `delta` prints the
exact sample size and “insufficient sample,” and does not print a savings,
capacity, improving, or worsening verdict. Existing baseline formats remain
readable and unchanged.

## Privacy boundary

The experiment file and JSON output contain no prompt or response text, model
name, project path, file path, hostname, finding detail, or raw child output.
The user-supplied experiment name is stored verbatim after validation. The
feature is offline and introduces no telemetry, network request, proxy, API
key, or provider dependency.

## Measuring the 1.8 sprint

The historical control is one completed task: development of 1.7 between the
Unix timestamps of the final 1.6 commit `78dd522` and final 1.7 commit
`a803603`, using the Personal project logs where the task was recorded. The
treatment is one completed task: implementation of this approved 1.8 spec in a
new clean Codex task, from its creation timestamp through the final reviewed
and green PR commit.

After the 1.8 binary is built, both windows are backfilled with `experiment
record`, compared with `experiment compare --json`, and saved as a redacted,
self-identifying artifact under `docs/experiments/`. The artifact includes the
control/treatment Git SHAs and exact aggregate counters, but no local paths.
The report must disclose that one sprint per arm is low-confidence and not a
causal A/B test.

## Error handling

- Reject `--tasks 0`, invalid names, invalid RFC 3339 timestamps, and
  `from >= to` through clear non-zero CLI failures.
- Reject `finish` for an unknown name and a second simultaneously active
  experiment with the same name without mutating state.
- Preserve valid state on scan, serialization, or write failure.
- Treat missing/unavailable source roots as zero records, not an error.
- Mark accounting incomplete when recognized project requests lack timestamps;
  keep their count out of interval totals and make `compare` refuse the record.
- Continue to tolerate unknown log record shapes exactly as the 1.7 parsers do.

## Architecture

Create `src/experiment.rs` as the sole owner of record validation, state
serialization, interval aggregation, comparison math, and CLI rendering. Add
the nested Clap command in `src/main.rs` and export the module from `src/lib.rs`.
Reuse `Request`, project-scoped parser wrappers, configuration loading,
`safeio::atomic_write`, and existing timestamp parsing. Do not alter detector
formulas or the version-1 Codex metadata index.

The release also updates `Cargo.toml`, release tests, workflow expectations,
README, changelog, accuracy documentation, roadmap, backlog, and benchmark
methodology to version 1.8.0. Rust 1.82 remains the MSRV and no new runtime
dependency is added.

## Test strategy

Development follows witnessed RED/GREEN cycles:

1. Unit tests for name/window validation, interval boundaries, saturating
   totals, composite session identity, exact one-task deltas, rounded multi-task
   views, overlap refusal, incomplete accounting, and state parsing.
2. Child-process CLI tests with isolated Claude/Codex fixtures for
   `start`, idempotent `finish`, historical `record`, `compare`, `list`, JSON
   redaction, corrupt-state preservation, and symlink refusal.
3. Regression tests proving `delta` emits no directional verdict below 100
   requests and retains its existing verdict at 100 or more.
4. Existing golden, parser, mutation, configuration, package, Python benchmark,
   Rust 1.82, RustSec, three-platform CI, and release workflow gates.
5. Packaged-source smoke tests plus the real v1.7/v1.8 experiment artifact.

## Acceptance criteria

- Every recognized timestamped request in a window is counted once; both
  boundaries have tests.
- An exact comparison is impossible unless both records are complete,
  finished, non-empty, and non-overlapping.
- The saved and JSON forms contain only the documented aggregate metadata.
- Existing `.codeunlimited.baseline.json` and `.codeunlimited.history.jsonl`
  files remain byte-compatible.
- A nine-request post-baseline sample reports insufficient evidence rather than
  “up 21%” or an equivalent verdict.
- The v1.7/v1.8 artifact exposes exact observed token totals per sprint and the
  derived difference without claiming causal savings.
- All local and GitHub release gates pass on the final branch SHA.

## Non-goals

- Proving causal savings from one historical comparison.
- Replaying the same paid LLM task twice.
- Scoring task quality automatically or reading task content.
- Changing provider limits, pricing, or model weights.
- Uploading experiment data or adding a hosted dashboard.
