# codeunlimited 1.6 Hardening Design

## Goal

Ship version 1.6.0 as a trust-focused release: calculations match the published
accuracy policy, explicit project scopes stay isolated, every mutating command
reports real filesystem outcomes, reports cannot overwrite one another, and the
release can be reproduced from one Git commit.

## Scope

The release covers the defects and gaps found in the 1.5 audit:

- safe, atomic, symlink-aware writes with propagated errors;
- per-project configuration resolution and exact Codex project matching;
- conservative detector totals without TTL inflation or cross-detector double
  counting;
- truthful `doctor`, report-output validation, stable JSON schema metadata,
  bounded day arguments, and non-destructive skill installation;
- regression, parser-contract, arithmetic-boundary, anonymization, and release
  tests;
- version 1.6.0 metadata, MIT license text, an explicit MSRV, synchronized
  documentation, and a release workflow that tests packaged artifacts and emits
  checksums;
- explicit legacy status for the Python prototype so it cannot masquerade as
  the production Rust CLI.

The branch is pushed and proposed through a pull request. Publishing to
crates.io and creating or moving a Git tag are outside this branch operation.

## Architecture

### Safe mutations

A new `safeio` module owns filesystem mutation. `atomic_write` writes to a
unique sibling temporary file, syncs it, and persists it to the destination.
Instruction-file updates reject symlink targets, reject unreadable/non-UTF-8
content without changing it, and create a non-overwritten backup before the
first replacement. Commands return `Result` internally and convert failures to
non-zero process exits at the CLI boundary.

Registry updates use a lock file around read-modify-write and the same atomic
writer. Report/history/badge and skill installation use the shared writer or an
explicit append path with propagated errors. Existing customized skills require
`--force`; forced replacement keeps a backup.

### Configuration and project identity

`Config::load_for(Option<&Path>)` replaces the process-global `OnceLock`.
Global configuration is loaded first, then an explicit project-root file
overlays fields. Scoped commands pass their canonical root. Machine-wide
commands use global configuration, while `fix --all` loads each registered
project's configuration and honors ignored-project rules before mutation.

Codex parsing retains a normalized full cwd key for scope comparison while
keeping a short basename label for reports. Only a `turn_context` record may set
model/cwd metadata; text embedded in unrelated records cannot do so.

### Detector accounting

Each detector retains its own finding total but also emits per-request impact
claims. The headline total is the sum of the largest claim for each request,
which is conservative and prevents the same prompt tokens being reclaimed by
multiple findings. Cache TTL expirations remain diagnostic detail but contribute
zero reclaimable tokens, matching `docs/ACCURACY.md`.

All token arithmetic uses saturating operations. Long-session calculations use
the configured threshold consistently and require at least one tail request.
Machine-readable output includes `schema_version: 1` and detector keys stable
across copy changes.

### Diagnostics and reports

`doctor` distinguishes healthy, unhealthy, and no-data states; no logs returns a
non-zero exit and never prints “All good.” Report output must designate a
Markdown path; `.html` is rejected so paired output cannot collide. History is
persisted only after report files succeed, and requested badge failures fail the
command.

Day windows accept 1 through 36,500 days. Larger or zero values are rejected by
argument parsing instead of wrapping timestamp arithmetic.

### Tests

Behavior is added test-first. Unit tests cover config overlays, arithmetic,
detector boundaries and accounting. Integration tests execute the real binary
against temporary directories for read-only writes, report collisions, no-data
doctor behavior, exact project scope, instruction idempotence, and skill
replacement. Parser fixtures cover malformed/unknown records and cwd collisions.
Release CI runs formatting, Clippy, tests, package verification, package install,
and artifact smoke tests on Linux, macOS, and Windows.

## Compatibility

Existing valid commands and report formats remain available. JSON gains fields
without removing existing ones. Project names remain short in human output.
Invalid invocations that previously returned misleading success now return a
non-zero code. The Rust package version becomes 1.6.0 with an MSRV of Rust 1.82.

The Python directory remains a prototype reference, is renamed at the packaging
surface to `codeunlimited-reference`, and exposes `codeunlimited-reference`
instead of shadowing the Rust `codeunlimited` executable.

## Release acceptance

The work is ready for review only when the repository is clean; all local CI
commands pass; the packaged crate installs and reports `codeunlimited 1.6.0`;
all regression reproductions return the corrected status; RustSec reports no
known vulnerable dependency; and the GitHub pull request checks are green.
