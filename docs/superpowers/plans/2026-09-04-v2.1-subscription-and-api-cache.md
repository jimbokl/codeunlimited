# codeunlimited 2.1 Subscription-First Cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` or `superpowers:executing-plans` and
> implement this plan test-first. This session uses executing-plans inline
> because the provider model, manifest migration, and accounting changes share
> one compatibility boundary.

**Goal:** Ship subscription-first cache-aligned Claude Code and Codex workers,
plus a distinct optional OpenAI/Anthropic API transport, with provider-correct
usage evidence and no unearned savings claim.

**Architecture:** Split prompt compilation into immutable instructions and a
bounded dynamic step. Store and hash the immutable artifact. Route it through
native CLI instruction flags for subscription providers and explicit cache
breakpoints for API providers. Keep the generic command adapter combined.

**Tech stack:** Rust 2021 / MSRV 1.82, clap, serde/serde_json, existing atomic
store and process harness, a pinned MSRV-compatible blocking HTTP client, local
mock HTTP tests only.

**Spec:**
`docs/superpowers/specs/2026-09-04-v2.1-subscription-and-api-cache-design.md`

## Constraints

- Do not issue a live Claude, Codex, OpenAI, or Anthropic request in tests.
- Subscription providers remain the default product path and require no API
  key.
- API credentials are environment-only and never persisted or printed.
- Every behavior change must be preceded by a focused failing test.
- Preserve v2.0 run readability and all v1.x observation commands.
- Never infer a cache hit; accept only a provider-reported cache-read counter.
- Keep Rust 1.82 green.
