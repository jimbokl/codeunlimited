# codeunlimited 1.9 Trust Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship codeunlimited 1.9.0 with safe instruction-block upgrades, reproducible evidence semantics, fail-closed installers, complete CI discovery, and honest product claims.

**Architecture:** Preserve the existing Rust CLI and stdlib Python evidence boundary. Make instruction mutation explicitly fallible, turn context-tax and paired A/B calculations into importable tested functions, validate installers against local fixtures, and bind evidence validation to immutable release commits rather than moving HEAD.

**Tech Stack:** Rust 2021 with Rust 1.82 MSRV, clap/serde/chrono and existing safeio; Python 3.10+ stdlib; POSIX sh; Windows PowerShell; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-04-v1.9-trust-release-design.md`

## Global Constraints

- No prompt, response, model, hostname, project name, session ID, or local path may enter published evidence.
- “Exact” applies only to observed integer counters; counterfactual and causal quantities are modeled or observational.
- Any ambiguous instruction block leaves the target byte-identical.
- Any unavailable or invalid checksum aborts before replacing an installed binary.
- Rust 1.82 remains the MSRV and no runtime dependency is added.
- Every production behavior change follows a witnessed RED/GREEN cycle.
- Version-facing metadata must agree on `1.9.0` before release.
