# codeunlimited 1.9.0 — trust the measurement

Version 1.9 makes the utility safer to adopt and harder to oversell.

## What changed

- Thirteen efficiency techniques are named and individually toggleable.
- Session guidance now balances useful context reuse against fresh-session boot
  cost; short related tasks should remain batched.
- Instruction upgrades reject malformed, duplicate, mixed, orphaned, or
  reversed markers without changing the file.
- The context-tax benchmark is portable, includes unfavorable sessions, and
  labels its bounded-context quantity as a model.
- A paired-task analyzer uses independent task pairs instead of treating
  correlated requests as independent observations.
- Installers require the release checksum and preserve the old binary on any
  download, validation, or smoke-test failure.

## Evidence update

The historical short-task A/B used approximately 17.4% more prompt tokens in
treatment even though its median request was lighter. The v1.7/v1.8
observational sprint comparison also used 29.686% more input tokens per
declared task in treatment. Neither result establishes causality, but both show
why request size alone is not the product KPI.

The primary outcome is now total input tokens per accepted comparable task,
with completion, quality, wall time, request count, and restart overhead as
guardrails. No fixed realized-savings percentage is claimed.

## Compatibility and migration

The Rust 1.82 MSRV remains unchanged. Existing experiment, baseline, history,
configuration, and report formats remain readable. Valid v1 instruction blocks
upgrade to v2 in place with a backup; ambiguous layouts require manual cleanup
and remain untouched.
